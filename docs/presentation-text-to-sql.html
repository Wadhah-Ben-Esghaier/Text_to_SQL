Du SQL à une lecture vérifiée

À terme, un LLM proposera une requête SQL à partir d’une question en français. Notre programme contrôlera sa syntaxe avant de lire la base.

Question de départ dans l’application visée

Quels sont les prénoms de trois clients ?

Requête écrite à la main pour ce jalon

SELECT FirstName
FROM Customer
LIMIT 3

De la requête à l’arbre

Texte SQLSELECT FirstName FROM Customer LIMIT 3

Lexer

Découpe le texte et note le type et la position de chaque jeton.

ValeurTypeCol.
SELECTKEYWORD1
FirstNameIDENTIFIER8
FROMKEYWORD18
CustomerIDENTIFIER23
LIMITKEYWORD32
3NUMBER38
—EOF39

Parser

Lit les jetons et applique les règles de la grammaire dans l’ordre.

  1. SELECT attend une colonne ici.
  2. FROM attend un nom de table.
  3. LIMIT attend un entier positif ou nul.

Si un jeton est inattendu, le parser indique sa position.

AST

L’arbre construit par le parser représente la structure de la requête.

SelectQuery
  • select_items
    • SelectItem
      • ColumnRef("FirstName")
  • from_table
    • TableRef("Customer")
  • limit = 3

sql_ast.py définit les dataclasses qui servent à représenter l’arbre.

Quatre commandes de démo

À lancer dans le terminal depuis la racine du dépôt.

Commande
python tests/t2s.py parse "SELECT FirstName FROM Customer LIMIT 3" --pretty
Sortie observée 
Arbre syntaxique (AST)
  SELECT     FirstName
  FROM       Customer
  LIMIT      3

parse affiche une vue de l’arbre par clause.

Commande
python tests/t2s.py parse "SELECT FROM Customer" --pretty
Extrait de la sortie 
Erreur de syntaxe
SELECT FROM Customer
       ^

Le parser attend une colonne après SELECT. Il rencontre FROM à la colonne 8.

Commande
python tests/t2s.py run "SELECT FirstName FROM Customer WHERE Country = 'France' ORDER BY CustomerId LIMIT 3" --pretty
Sortie observée 
Résultat Chinook (3 lignes)
FirstName
---------
Camille
Dominique
Marc

run vérifie d’abord la syntaxe, puis envoie la requête SQL acceptée à SQLite en lecture seule.

Commande
python tests/t2s.py run "DELETE FROM Customer" --pretty
Extrait de la sortie 
Requête refusée avant exécution
DELETE FROM Customer
^

Le parser attend SELECT. L’erreur arrête run avant l’ouverture de SQLite.

Deux protections, deux vérifications

Les tests automatiques comparent le comportement du programme au résultat attendu.

Parser

Le test passe DELETE FROM Customer à run_query. Il vérifie l’erreur du parser et l’absence d’appel à la fonction qui ouvre la connexion.

SQLite

Un autre test envoie le même DELETE directement à SQLite, sur une copie temporaire de Chinook. La connexion en lecture seule refuse la suppression.

python -m unittest discover -s tests -q 17 tests réussis · OK

La suite couvre aussi 16 requêtes valides et 5 invalides dans les cas de test du parser.
