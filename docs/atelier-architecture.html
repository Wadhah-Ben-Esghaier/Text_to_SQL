Pourquoi ce qui passe sur les flèches compte autant

Tant que ce qui passe sur une flèche ne change pas, chacun peut réécrire l'intérieur de son module sans prévenir les autres, et deux personnes peuvent coder les deux bouts en parallèle. S'il change, ou s'il n'est écrit nulle part, tout ce qui est derrière la flèche peut casser.

Un exemple chez vous. Votre parser lit chaque jeton en le déballant à quatre places : token_type, value, _, _ = self.current. Le contrat entre le lexer et le parser est donc « un tuple de exactement quatre champs, dans cet ordre ». Il n'est écrit nulle part : si l'un de vous ajoute au lexer un cinquième champ (la position de fin du jeton, par exemple), le parser plante sur la première requête :

ValueError: too many values to unpack (expected 4)

Avec une dataclass Token(type, value, line, column), le contrat est écrit, le parser lit token.type, et ajouter un champ ne casse rien.

Trois questions à vous poser

Répondez entre vous, puis dépliez.

Un jeton est un tuple (type, valeur, ligne, colonne) : que se passe-t-il si quelqu'un change l'ordre des champs ?

Tout le code qui lit t[1] ou t[3] casse sans message clair. Un NamedTuple ou une dataclass Token rend le contrat explicite, et l'éditeur vous aide.

query_cursor appelle parse_sql(sql) puis exécute le texte : que devient l'arbre ?

Il est jeté : le parser sert de garde. C'est suffisant aujourd'hui, mais le vérificateur de schéma aura besoin de l'arbre, il faudra le garder.

Pourquoi le code qui ouvre la base est-il dans tests/ ?

Parce que t2s.py est à la fois la ligne de commande, l'accès à la base et l'enchaînement. C'est du code de l'application, pas un test : sa place est dans src/. Vous verrez à l'étape des ajouts pourquoi ça compte.

Étape 4 · généraliser

Ce que vous avez construit a des noms

Où on en est
Vous avez construit votre architecture à partir de votre cas.
Objectif
Mettre dessus les noms du cours : ce sont les mots que vous utiliserez en soutenance.

Le cours a présenté des motifs d'architecture. Vous venez d'en assembler plusieurs sans les nommer : une vraie application en compose toujours plusieurs.

Pipeline

Votre flux est un pipeline de compilateur : texte → jetons → arbre → lignes. Chaque étape transforme une représentation en une autre, et peut refuser. C'est pourquoi chaque étape se vérifie seule.

Couches

Entrées (ligne de commande, page web), cœur (lexer, parser, vérificateur, enchaînement), bord (modèle, base). Les flèches vont des entrées et du bord vers le cœur.

Client-serveur

Ollama est un serveur HTTP local, votre code en est le client. Avec la page web, on retrouve le 3-tiers du cours : navigateur, serveur, base.

MVC

La page web affiche la question, la requête, le refus ou la table : c'est une vue. Elle appelle pipeline.py, elle ne construit jamais de SQL elle-même.

Les 12 requêtes de référence

Les questions et les requêtes attendues utilisées pour préparer cette page : un bon test pour votre grammaire, et plus tard pour mesurer le modèle.

1How many customers are there?SELECT COUNT(*) FROM Customer
2List the names of all genres.SELECT Name FROM Genre
3Which customers live in France? Give first and last names.SELECT FirstName, LastName FROM Customer WHERE Country = 'France'
4What are the 5 longest tracks (name and milliseconds)?SELECT Name, Milliseconds FROM Track ORDER BY Milliseconds DESC LIMIT 5
5How many invoices were billed in each country? Order by number of invoices, highest first.SELECT BillingCountry, COUNT(*) AS n FROM Invoice GROUP BY BillingCountry ORDER BY n DESC
6List the titles of the albums by the artist named 'AC/DC'.SELECT a.Title FROM Album a JOIN Artist ar ON a.ArtistId = ar.ArtistId WHERE ar.Name = 'AC/DC'
7List the names of tracks in the genre 'Jazz' that are longer than 400000 milliseconds.SELECT t.Name FROM Track t JOIN Genre g ON t.GenreId = g.GenreId WHERE g.Name = 'Jazz' AND t.Milliseconds > 400000
8Which employee is the support representative of the customer with CustomerId 1? Give first and last name.SELECT e.FirstName, e.LastName FROM Customer c JOIN Employee e ON c.SupportRepId = e.EmployeeId WHERE c.CustomerId = 1
9What is the total amount invoiced per customer? Show first name, last name and total, for customers whose total is above 45.SELECT c.FirstName, c.LastName, SUM(i.Total) AS total FROM Customer c JOIN Invoice i ON i.CustomerId = c.CustomerId GROUP BY c.CustomerId, c.FirstName, c.LastName HAVING SUM(i.Total) > 45
10How many tracks does each genre have? Show genre name and count, top 3.SELECT g.Name, COUNT(*) AS n FROM Track t JOIN Genre g ON t.GenreId = g.GenreId GROUP BY g.Name ORDER BY n DESC LIMIT 3
11What is the average track length in milliseconds for each media type? Show media type name and average.SELECT m.Name, AVG(t.Milliseconds) AS avg_ms FROM Track t JOIN MediaType m ON t.MediaTypeId = m.MediaTypeId GROUP BY m.Name
12Which 3 artists have the most albums? Show artist name and number of albums.SELECT ar.Name, COUNT(*) AS n FROM Album a JOIN Artist ar ON a.ArtistId = ar.ArtistId GROUP BY ar.Name ORDER BY n DESC LIMIT 3
